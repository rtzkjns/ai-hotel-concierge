## 3. Безопасность

| Требование | Статус | Как |
|---|---|---|
| GDPR | ✅ | Право на удаление (консоль «Удаление ПД» + распознавание запроса ботом, тип data_deletion), retention, минимизация ПД в логах |
| PCI DSS | ✅ | Ввод карты только на хостед-странице Exely (ссылка) — отель вне card-data scope; в боте карты не появляются никогда |
| Шифрование при передаче (TLS 1.2+) | 🔑 | Деплой-требование: HTTPS-терминация на сервере (Caddy), в runbook. Ждёт VPS |
| Хранение логов ≤ 90 дней | ✅ | Автоматический retention-job: events чистятся, истории неактивных диалогов опустошаются, sessions выметаются |
| Роль администратора | ✅ | Консоль: роль admin (полный доступ) |
| Роль менеджера по продажам (MICE) | ✅ | Роль mice_manager: метрики, MICE-заявки, только свои/неразобранные перехваченные чаты, ПД маскируются |
| Маскирование паспортных данных | ✅ | maskPII: 9–12-значные числа (ИИН/паспорт) скрываются полностью — во всех логах и уведомлениях; эвал passport-in-chat зелёный |
| Маскирование телефонов | ✅ | maskPII: телефоны до первых 2 + последних 2 цифр |
| Удаление ПД по запросу гостя | ✅ | Консоль (admin, с подтверждением, защита от опечатки в id) + событие аудита |
| Ограничение количества запросов | ✅ | Sliding-window rate-limiter per отправитель (20/мин) |
| Фильтрация спама | ✅ | Повторы ×3, оверсайз-сообщения — молчаливый дроп с событием |
| Антибот-защита веб-виджета | ✅ | Одноразовый токен страницы с TTL 1 ч, привязка к senderId (нельзя наштамповать сессий), 4001 на невалидный hello |

## 4. API-интеграции

| Пункт ТЗ | Статус | Как |
|---|---|---|
| 4.1 Edelweiss: получение доступности | ✅ | Live Exely Search (property 801), проверено против прода |
| 4.1 Получение тарифов | ✅ | Search (цены/тарифы) + Content API (категории, описания, 13 тарифных планов) |
| 4.1 Создание бронирования | 🔑 | ExelyReservation verify→create готов и проверен вплоть до живого запроса; ждёт Reservation-scope (403). До этого: персональная bookingFormLink + заявка |

| 4.1 Отмена бронирования | ✅/🔑 | cancel через API при scope; без scope — заявка персоналу на ручную отмену. Всегда с явным подтверждением гостя (guardrail в оркестраторе) |
| 4.2 TravelLine: тарифы/доступность/бронь | ✅ | = Exely (пункт 4.1) |
| 4.2 Проверка промокодов | 🚧 | Публичный API Exely промокоды не принимает (проверено по Swagger — поля нет). Реализовано лучшее возможное: бот направляет гостя к кнопке «Ввести промокод» на странице оплаты (подтверждена на kazzhol.com) + уведомляет команду для подтверждения кода |
| 4.3 Платёжный шлюз: создание/статус/отмена | ⏸ | Интерфейс PaymentGateway в коде готов (точка подключения). Решение заказчика 2026-07-13: v1 — оплата по ссылке Exely; прямой шлюз (Halyk ePay invoice-links — проверенный вариант) — после пилота |
| 4.4 AMO CRM: лид/статус/MICE | 🔑 | Интерфейс AmoCrmClient + стаб (лиды фиксируются в БД и консоли). Реальный клиент включается при получении AMO-токена (~1 день работы) |
| 4.5 WhatsApp Business API | 🔑 | Полный адаптер Cloud API (вебхуки, подписи, typing, голосовые, split-отправка) — ждёт Meta-доступов |
| 4.5 Instagram Graph API | 🔑 | Адаптер-каркас (parse + send) — ждёт Meta + привязки IG-аккаунтов |
| 4.5 Telegram Bot API | ✅ | Работает (гостевой канал; публикация ссылки — по решению отеля) |
