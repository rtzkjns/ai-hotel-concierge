# Переезд Instagram на новое Meta-приложение

Составлено 2026-08-17 после безвозвратной блокировки FB-аккаунта «Mandsd Nihhmeni», который был
единственным администратором приложения `kazzhol-social`.

## Почему `kazzhol-bot` не подошёл, а `kazzhol-social` подошёл

Разница ровно одна и она решает всё:

| | `kazzhol-bot` (1726503178626408) | `kazzhol-social` (28263166043309368) |
|---|---|---|
| Бизнес-портфель | привязан к «Бернер Александр's Business» (373990573160727) | **не привязан ни к какому** |
| Верификация бизнеса | требуется, статус Incomplete | **не требуется вообще** |
| Кнопка Publish | заблокирована | нажалась сразу |
| Вебхуки Instagram | не идут (приложение не опубликовано) | идут |

**Meta требует верификацию бизнеса только когда приложение ЗАЯВЛЕНО (claimed) бизнес-портфелем.**
Непривязанное приложение публикуется свободно. А публикация обязательна: в панели вебхуков Meta
пишет дословно — «No production data, including from app admins, developers or testers, will be
delivered unless the app has been published».

Отсюда правило: **новое приложение НЕ привязывать к бизнес-портфелю**, пока портфель не прошёл
верификацию. Устойчивость обеспечивается не портфелем, а несколькими администраторами самого
приложения — именно этого и не хватило: у `kazzhol-social` был 1 админ и 0 остальных ролей.

## Пошагово

Делать из ЗДОРОВОГО Facebook-аккаунта (не заблокированного, желательно не личного профиля
одного человека).

1. **Создать приложение.** developers.facebook.com → Create App → тип **Business**.
   На шаге выбора бизнес-портфеля выбрать **«No business portfolio selected»** (или пропустить).
   ⚠️ Не выбирать портфель Бернера и вообще никакой — иначе получите второй `kazzhol-bot`.

2. **СРАЗУ добавить ещё 2 администраторов.** App Roles → Roles → Add People → **Administrator**.
   Это самый важный шаг во всём гайде: именно его отсутствие стоило нам приложения.
   Добавить владельца и/или доверенного сотрудника, чтобы блокировка одного человека
   больше никогда не отрезала доступ.

3. **Добавить use case** «Manage messaging & content on Instagram»
   (это «Instagram API with Instagram Login», Facebook-страница НЕ нужна).

4. **Settings → Basic** — без этого не даст опубликовать:
   - Privacy Policy URL: `https://kazzhol.128-140-86-176.sslip.io/privacy`
   - Terms of Service URL: `https://kazzhol.128-140-86-176.sslip.io/terms`
   - User data deletion → «Data deletion instructions URL»: `https://kazzhol.128-140-86-176.sslip.io/privacy`
   - Category: **Messaging**
   - Save Changes

5. **Опубликовать.** Dashboard → Publish → должно быть написано «All required app settings are
   complete», кнопка Publish активна → нажать. Проверить, что статус стал **Published**.
   Если кнопка серая и требует Business verification — значит на шаге 1 всё-таки привязался
   портфель; отвязать его или создать приложение заново.

6. **Instagram → API setup with Instagram login** — записать **Instagram App ID** и
   **Instagram App Secret** (это ОТДЕЛЬНЫЕ значения, не Meta App ID).

7. **Настроить вебхук** — именно на этой странице продукта, а не на общей вкладке Webhooks
   (Meta прямо пишет: «Webhook configurations for Instagram API with Instagram business login are
   supported only within the product itself»):
   - Callback URL: `https://kazzhol.128-140-86-176.sslip.io/webhooks/instagram`
   - Verify token: значение `WHATSAPP_VERIFY_TOKEN` из `.env` (код переиспользует его для IG)
   - Verify and save → в таблице Webhook fields включить поле **messages** (Subscribe)

8. **Подключить 4 аккаунта** через **«Set up Instagram business login»**.
   ⚠️ НЕ через кнопку «Add account» в шаге «Generate access tokens» — она выдаёт всего лишь роль
   **тестера**, а не production-подключение.
   Аккаунты: `kazzhol_almaty_hotel`, `kazzhol_astana_hotel`, `kazzholpark_almaty_hotel`,
   `kazzhol_seven_almaty`.

9. **Передать токены разработчику.** Дальше делается на сервере:
   - `INSTAGRAM_TOKEN_<HOTEL>` — новые токены
   - `INSTAGRAM_IG_ID_<HOTEL>` — business id (`17841…`, НЕ меняется) + НОВЫЙ app-scoped id через
     запятую: при смене приложения app-scoped id меняется, а адаптер маппит оба
   - `POST /me/subscribed_apps?subscribed_fields=messages` по каждому аккаунту
   - рестарт сервиса, сквозной тест

## Как ПРОВЕРИТЬ, что портфель не привязался (три признака)

Проверять сразу после создания, до всех остальных шагов. Если сработал хоть один — приложение
заявлено портфелем, надо отвязать или пересоздать:

1. В списке `developers.facebook.com/apps/` в карточке приложения **есть строка `Business:`**
   (у `kazzhol-bot` было «Business: Бернер Александр's Business», у `kazzhol-social` — ничего).
2. В адресной строке на страницах приложения **появляется `business_id=…`**
   (Facebook дописывает его сам, когда приложение принадлежит портфелю).
3. На странице Publish **есть раздел Business verification**. У правильного приложения там только
   «All required app settings are complete» и активная кнопка Publish.

Сама страница `My Apps` — это ЛИЧНЫЙ список всего, где у вас есть роль, независимо от портфеля.
То, что два приложения лежат рядом, НИЧЕГО не говорит об их принадлежности.

## Про аккаунт, из которого создавать

- Аккаунт должен быть **живой и «настоявшийся»** — например, владельца или доверенного сотрудника.
- ⚠️ **Свежесозданный аккаунт — отдельный риск.** Meta часто ограничивает новые профили, особенно
  если они заведены взамен забаненного, с того же устройства и IP. Тогда история повторится.
- Место создания одно для всех — `developers.facebook.com`. Решает не «где создавать», а **что
  выбрать в поле бизнес-портфеля на шаге создания** («No business portfolio selected»).
- Устойчивость даёт НЕ портфель, а несколько администраторов приложения (шаг 2).

## Чек-лист «не повторить ошибок»

- [ ] Приложение НЕ привязано к бизнес-портфелю
- [ ] Администраторов **минимум 3**, а не один
- [ ] Статус приложения — **Published** (иначе входящих не будет вообще)
- [ ] Подключение через Business Login, а не через роль тестера
- [ ] Вебхук настроен внутри продукта Instagram, поле `messages` — Subscribed
- [ ] Все 4 аккаунта, включая Seven
- [ ] Проверен реальный входящий DM от живого человека (это звено ни разу не подтверждалось)
