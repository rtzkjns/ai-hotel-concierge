# Что нужно от Казжола / владельца для полноценной работы бота

**Дата:** 2026-07-11 · **Продукт:** AI-менеджер отеля по ТЗ 1 (`docs/specs/2026-07-10-tz1-ai-bot.md`)

Софт готов и работает в stub-режиме (веб-виджет + Telegram + консоль персонала).
Ниже — весь список внешних зависимостей, сгруппированный и помеченный:

- **🔴 BLOCKS-LAUNCH** — без этого нельзя запустить продукт в том виде, который обещан ТЗ;
- **🟢 OPTIONAL** — включается позже, бот честно деградирует без этого.

## 1. Meta / WhatsApp — 🔴 BLOCKS-LAUNCH (самый длинный срок — начать первым)

WhatsApp — главный канал по ТЗ. Технически адаптер готов и работает с тестовым
номером Meta; для продакшена нужно:

- [ ] **Доступ к Meta Business аккаунту.** Мы пока НЕ внутри — это первый шаг, и мы
  НЕ исходим из того, что аккаунт надо пересобирать. План: получить админ-доступ →
  посмотреть состояние → **переиспользовать, если аккаунт жив** (верифицирован, без
  ограничений); пересборка — только запасной вариант (тогда понадобятся документы
  компании для Business verification).
- [ ] **Business verification** (если не пройдена) — документы юрлица.
- [ ] **WABA (WhatsApp Business Account)** в этом Business Manager.
- [ ] **Подключить 3 номера** (Алматы, Астана, Park Almaty — или решение «один номер
  на сеть»). ⚠️ **ВАЖНО: номер, подключённый к Cloud API, отвязывается от обычного
  приложения WhatsApp/WhatsApp Business на телефоне** — персонал больше не сможет
  переписываться с него из приложения; все ответы пойдут через нашу консоль. Это
  надо явно согласовать с ресепшн заранее.
- [ ] Выдать нам от WABA: `WHATSAPP_ACCESS_TOKEN` (permanent token), phone_number_id
  каждого номера, и согласовать `WHATSAPP_VERIFY_TOKEN` / `WHATSAPP_APP_SECRET`.
- [ ] **Instagram** (DM-автоответы) — 🟢 OPTIONAL, позже: перевести 3 аккаунта в
  Professional, привязать к страницам Facebook, выдать доступ. Каркас-адаптер уже в коде.

## 2. Exely (TravelLine / Edelweiss) — 🔴 BLOCKS-LAUNCH для живых цен и брони

Search/Content уже работают на выданных кредах (property 801 = Kazzhol Almaty).

- [ ] **Включить scope Reservation API** в Экстранете (сейчас API отвечает **403** на
  создание брони): *Настройки отеля → Подключения по API → у подключения отметить
  доступ к бронированиям («создание бронирований»), Сохранить и открыть доступ*.
  Если пункта нет — запросить у поддержки Exely включение раздела API/scope в тариф.
- [ ] **Подтвердить структуру кабинетов:** один кабинет покрывает все 3 отеля, или у
  Астаны и Park Almaty свои кабинеты? Нужны **property id** (и креды кабинета, если
  отдельный) для каждого отеля — сейчас живые данные есть только у Алматы (801).
- [ ] До включения scope бот работает честно: живые цены + персональная ссылка на
  форму бронирования (bookingFormLink) + заявка персоналу. Это не блокирует запуск
  «продаж», но блокирует «полную бронь в чате» из ТЗ.

## 3. Платежи — 🟢 OPTIONAL (сегодня закрыто ссылкой)

- [ ] Онлайн-оплата уже идёт через форму Exely (bookingFormLink) — этого часто
  достаточно. Если нужна **оплата прямо в чате** — решить, какой шлюз (ePay Halyk,
  Kaspi, другой) и выдать креды; интерфейс `PaymentGateway` в коде готов под своп.

## 4. AMO CRM — 🟢 OPTIONAL

- [ ] Access token + id воронки/этапов, куда складывать лиды и MICE-заявки.
  Пока лиды пишутся в БД бота и видны в консоли + уходят в Telegram-чат персонала.

## 5. Распознавание голосовых — 🟢 OPTIONAL

- [ ] Ключ OpenAI (или Groq/Google — интерфейс готов) для транскрибации голосовых.
  Без ключа бот честно просит написать текстом.

## 6. База знаний по отелям — 🔴 BLOCKS-LAUNCH (качество ответов)

По каждому из 3 отелей подтвердить/дополнить факты (сейчас — с офиц. сайта + оценки):

- [ ] Часы завтрака и тип (шведский стол?), рестораны и их часы;
- [ ] Парковка (платная/бесплатная, где), бассейн/фитнес (AquaFit в Алматы — часы, входит ли в тариф);
- [ ] Трансфер (есть ли, цены), ранний заезд / поздний выезд (политика и цены — это же upsell!);
- [ ] Политика отмены, дети/доп. кровати, животные, способы оплаты на месте;
- [ ] Конференц-залы: названия, вместимость, оборудование, вилки цен, кофе-брейки (для MICE);
- [ ] **Подтвердить «примерные цены от…»** в базе знаний или дать актуальные ориентиры.
- [ ] Языки: контент принимаем на RU — бот сам отвечает на KK/EN/ZH.

## 7. Хостинг — 🔴 BLOCKS-LAUNCH

- [ ] VPS (достаточно 1–2 GB RAM) + домен/поддомен, либо мы хостим и выставляем счёт.
  Требования ТЗ закрываются runbook'ом в README: HTTPS/TLS 1.2+, аптайм-мониторинг
  (SLA 99.5%), бэкап SQLite, ретеншн логов 90 дней встроен.

## 8. Персонал и эскалации — 🔴 BLOCKS-LAUNCH (операционка)

- [ ] **Список аккаунтов консоли:** кто получает доступ, с ролями
  (`admin` — всё; `mice_manager` — MICE-заявки + перехваченные чаты).
- [ ] **Дежурный Telegram-чат**: создать группу, добавить бота, дать chat id
  (`STAFF_GROUP_CHAT_ID`) — туда падают эскалации, лиды и MICE-уведомления.
- [ ] Согласовать регламент: кто и в какие часы отвечает на «взятые» чаты,
  что делать с запросом на удаление персональных данных (кнопка в консоли есть).

## 9. Китайский язык — 🟢 OPTIONAL

- [ ] Носитель китайского для выборочной проверки ответов (ZH включён и проходит
  автотесты, но native QA перед активным маркетингом на китайском рынке желателен).

## Кратчайший путь к запуску

1. **§1 Meta/WhatsApp** — доступ к Business аккаунту сегодня; это самый длинный хвост.
2. **§2 Exely** — один клик в Экстранете (scope Reservation) + property id остальных отелей.
3. **§6 знания + §8 персонал** — час встречи с управляющим каждого отеля.
4. **§7 хостинг** — день работы.

Всё из 🟢 подключается позже без переделок: интерфейсы (платежи, CRM, транскрибация,
Instagram) уже в коде.
