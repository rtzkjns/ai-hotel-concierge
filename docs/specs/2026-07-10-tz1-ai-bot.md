Дата: 2026-07-10. Источник требований: `~/Downloads/Техническое задание 1.docx` (строго) + утверждённое видение пользователя (диалог 2026-07-10). Заменяет прежнюю концепцию P1 в части идентичности и каналов.

## 0. Сводка решений (утверждено пользователем)

## 1. Цели (из ТЗ)

Многоязычный AI-бот, полностью интегрированный в процессы отеля Kazzhol Almaty: продажи, бронирования, MICE, гостевой сервис, upsell, аналитика. Задачи: снизить нагрузку на ресепшен, увеличить прямые брони через сайт и WhatsApp, автоматизировать MICE-запросы, повысить конверсию upsell (ранний заезд, поздний выезд, апгрейд категории), скорость и качество ответа. Бот должен закрывать рабочие процессы лучше живого менеджера.

## 2. Языки

**RU / KK / EN / ZH (китайский — требование ТЗ).** Автоопределение по сообщениям гостя, переключение на лету, понимание казахско-русского суржика, сленга, опечаток, голосовых.

## 3. Архитектура

```
Гость → Канал (WhatsApp | Telegram | Instagram | Web-виджет)
      → ChannelAdapter (нормализация вход/выход)
      → Engine: Session Manager (SQLite) → Orchestrator (Claude + тулы) → Style Engine
      → Интеграции: Exely (PMS Edelweiss + CM TravelLine = один API), Payments, AMO CRM
      → Консоль персонала (takeover, лиды, MICE, метрики) с ролями
```

- **Exely = TravelLine (ребренд) и фронтит Edelweiss PMS** → пп. 4.1 и 4.2 ТЗ закрываются одной интеграцией Exely Connect (`connect.hopenapi.com`): Search (доступность/цены/checksum/bookingFormLink), Content (категории/тарифы/услуги), Reservation v1 (verify→create→get→cancel). Порт готового клиента из `kazzhol-portal/src/Integrations/Exely/*`.
- Один процесс Node/TS (fastify): webhooks + WS + консоль + статика виджета.
- Хранилище: SQLite (better-sqlite3), интерфейс репозитория = точка свопа на Postgres.

## 4. Каналы (ТЗ 4.5)

| Канал | Статус в этой сборке |
|---|---|
| WhatsApp Business API | Полный адаптер Cloud API v20+: verify webhook, приём text/audio/image, отправка с разбивкой + typing, mark-as-read. Работает с тестовым номером Meta; прод ждёт верификации |
| Web-виджет (WebSocket) | Полностью рабочий: WS endpoint + встраиваемая HTML/JS страница чата, анти-бот токен, rate limit. Демо доступно сразу |
| Telegram Bot API | Порт существующего бота на адаптерную схему (работает с текущим токеном) |
| Instagram Graph API | Каркас-адаптер (stub): интерфейс + обработка вебхука, ждёт Meta-доступа |

Голосовые: входящие audio → транскрибация (без внешних ключей — заглушка с честным «не смог прослушать, напишите текстом», интерфейс `Transcriber` под Whisper/Groq/Google при появлении ключа; если задан OPENAI_API_KEY / GROQ_API_KEY — живая транскрибация).

## 5. Мозг: тулы оркестратора

1. `check_availability` — живой Exely Search (property 801), цены/наличие/варианты. НИКОГДА не выдумывать цены.
2. `get_room_info` — Exely Content: категории, описания, услуги, фото-ссылки.
3. `create_booking` — Reservation verify→create (флаг `EXELY_BOOKING_ENABLED`, default false). При выключенном флаге/403: заявка в БД + персональный bookingFormLink (диплинк с датами) + уведомление персоналу. Перед create — подтверждение гостем деталей.
4. `get_booking_status` / `cancel_booking` — Reservation get/cancel + расчёт штрафа; отмена только после явного подтверждения гостя.
5. `check_promo_code` — Exely Search c промо-параметром, если API поддерживает; иначе честный stub («проверим и вернёмся») + заявка.
6. `create_payment` / `check_payment_status` — интерфейс PaymentGateway, сейчас stub (онлайн-оплата идёт через bookingFormLink/виджет Exely). Точка подключения реального шлюза (ePay и т.п.).
7. `submit_mice_request` — сбор MICE-заявки (даты, численность, залы, кофе-брейки, бюджет) → БД + AmoCrmClient (stub → лог в БД) + мгновенное уведомление MICE-менеджеру.
8. `capture_lead` — любой недожатый интерес → лид в БД + CRM stub.
9. `escalate_to_human` — крайняя мера (правила ниже).
10. Upsell: не отдельный тул, а обязательная механика промпта + поля `upsell_offered/accepted` в брони: при брони предлагать ранний заезд/поздний выезд/апгрейд по данным Content/цен; событие в аналитику.

Кросс-отель: конфиг per-property; при вопросе про другой отель Kazzhol — отвечает знаниями того отеля и, при наличии его Exely id, живыми данными; бронь другого отеля в том же чате.

## 6. Style Engine (очеловечивание)

Слой между мозгом и отправкой:
- Разбивка ответа на 1–3 коротких сообщения (маркер `|||` от модели + fallback-эвристика), паузы между ними, typing-индикатор.
- Задержка ответа: функция от длины (мин/макс границы), но SLA ТЗ ≤5 сек до первого действия (typing = мгновенная реакция, текст может прийти позже — фиксируем метрику).
- Зеркалирование: регистр («ты»/«вы»), язык, эмодзи-плотность гостя.
- Анти-AI-паттерны: запрет канцелярита, буллет-простыней, шаблонных открытий («Конечно! Я с радостью…»), одинаковых концовок. Живые связки по-русски/казахски. Правила будут дополнены из deep-research (задача 8).
- Честность: на вопрос «ты бот?» — лёгкое «да, я бот-ассистент отеля 🙂 но бронирую не хуже живых» без дисклеймер-простыни. Приветствие при первом контакте коротко обозначает ассистента отеля.

## 7. Безопасность и SLA (ТЗ 2–3)

- Rate limiting per sender (окно/минута) + спам-фильтр (повторы, флуд, мусор) + анти-бот токен для веб-виджета.
- Маскирование ПД в логах и уведомлениях персоналу: телефоны `+7 7** *** **53`, паспорта — полностью. Утилита `maskPII()` применяется во всех log/notify путях.
- Retention: job очистки истории/логов старше 90 дней (запуск при старте + раз в сутки).
- Удаление ПД по запросу гостя: команда консоли + распознавание запроса ботом → эскалация с типом `data_deletion`.
- Роли консоли: `admin` (всё) и `mice_manager` (MICE-заявки + свои диалоги). Basic auth (bcrypt-хэши в БД), сессии.
- TLS 1.2+, uptime 99.5%, время платежа ≤20с — деплой-требования, фиксируются в runbook (README), не в коде.
- Секреты только в `.env`/локальном конфиге (gitignored). Логи без токенов.

## 8. Аналитика (ТЗ: «аналитика»)

Таблица `events` (append-only): message_in/out per channel/language, booking_created/failed, lead_captured, mice_created, upsell_offered/accepted, escalation, payment_*. Консоль: сводка (диалоги/день, конверсия в бронь, доля языков, эскалации, upsell-конверсия, p50/p95 времени ответа — SLA-метрика).

## 9. Консоль персонала

Мини-веб (та же нода): логин с ролями → список диалогов (live, канал/язык/статус) → просмотр переписки (ПД маскируются для не-админа) → «взять чат» (бот замолкает, менеджер пишет с того же номера через адаптер) → «вернуть боту» → лиды/брони/MICE-заявки → метрики. Уведомления дежурным: Telegram staff-чат (уже есть) + событие в консоли.

## 10. Тесты и качество

- Vitest: все чистые модули (store, style engine, orchestrator с фейк-клиентом, exely-клиент на фейк-fetch, rate limiter, masking, retention).
- `npm run typecheck` — ворота.
- Эвал-набор: `tests/evals/scenarios.md` — 20+ сценариев (RU/KK/EN/ZH, сленг, голосовое, злой гость, MICE, промокод, отмена, «ты бот?», попытка джейлбрейка) + скрипт прогона с LLM-судьёй (запускается вручную, требует API-ключ).
- Живой smoke: Exely search против прод-API (ручной скрипт, креды из .env).
